# Repository Working Instructions

## RenoApp

Before planning, reviewing or changing RenoApp behavior, flows, UI or messaging,
read [RenoApp product principles](docs/renoapp-product-principles.md) and the
relevant feature documents linked from it.

- Distinguish agreed product principles, documented implementation and open
  questions. Do not implement an open proposal as an approved requirement.
- Check actual code and configuration before claiming how a feature works.
- Surface conflicts with the principles before changing product behavior. When
  the user explicitly changes a product decision, update the document and its
  decision log as part of that work.
- These product principles apply to RenoApp, not automatically to other modules.
- Keep unrelated parallel work untouched and out of task-specific commits.
